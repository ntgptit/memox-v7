The four things a screen can be doing instead of showing content — loading, empty, failed, or asking — plus the two modals. Empty and error are separate components on purpose: "you have finished everything due today" is good news, and rendering it in error styling tells the user something is broken when nothing is. Every string here arrives already localized; none of these components reads a catalogue, and none of them decides how a failure reads.

MxAsyncView — the policy, not the branch

It renders one of the three states above, and what it centralises is the answer to "does a refresh show a spinner". First load: spinner — there is nothing to keep showing, so a screen never presents stale data as fresh. Refresh: the previous value stays, because replacing a populated list with a spinner on every resume is motion in place of information. Reload: spinner, because a dependency changing means the previous value answers a question nobody is asking any more. Failure: the caller's own copy — there is deliberately no default, since a generic "something went wrong" is how every screen ends up with the same unhelpful sentence.
