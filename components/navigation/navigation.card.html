Navigation

Four components that answer four different questions, which is why they are four and not one with a mode. Where am I in the app — the bottom bar, siblings at a fixed level. Where am I in the tree, and how do I get back up — the breadcrumb, an arbitrary number of levels. What is this screen — the shell, which owns the gutter and the app bar so no screen picks its own. Which of these — the search field. None of them knows the router; they take an index and a callback and never navigate.

Why 120px per destination

An even split puts two destinations at the quarter and three-quarter marks, one hard against each edge, with a void between them that reads as a missing tab. Capping the row per destination centres them — and at four the row wants more width than a phone has, so the cap disarms itself and Material's even split takes over. A fixed maximum would have to be revisited every time a tab is added.

Why the breadcrumb scrolls

A path can be ten deep and a 320-wide screen at a 2× text scale fits about one and a half names. Wrapping turns a deep path into five lines of chrome above the content it exists to help you scan; collapsing the middle behind an ellipsis hides exactly the steps a user goes to a breadcrumb to find. Scrolling hides nothing and costs nothing when the path is short.
