Containers

A container is a surface that carries a hue without carrying an action. Each comes with the colour that goes on it, and the pair is checked against itself — a container used with any other foreground is a contrast failure waiting for the one screen nobody re-checked.

These were the roles the audit found had gone wrong quietly. fromSeed had produced a pink tertiary and an error red competing with danger, in hue families the app never uses. None had surfaced only because the MVP had no dialog, sheet, navigation bar, menu or chip yet — leaving them generated meant those screens would render as a different app.

Rules
  • Never split a pair. on-primary-container goes on primary-container and nowhere else.
  • A container is not an action. A filled button is primary / on-primary. A container that looks pressable is a control the user will press.
  • error is danger. One red, not two systems that drift apart the first time one of them is adjusted.
  • The *Fixed family is brightness-independent by definition, so both themes take the same light-container values. Nothing reads them today — which is exactly the argument that left a pink tertiary undetected until someone went looking.
