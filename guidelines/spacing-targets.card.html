Targets

48 is the smallest side of anything a finger has to hit, and it is not part of the spacing scale — it is a floor, not a step. A control below it is reachable on a desk and missed on a bus, and the miss looks like the app ignoring the tap rather than the user hitting beside it.

It lives in the stylesheet and never in a prop, so there is nothing for a screen to pass. Material's VisualDensity.compact would have been the shorter route to a tighter layout, and it subtracts 8 from every button — taking the icon button to 40×40, under the floor a thumb needs and under the floor the button was measured against.

Every control, at its target

The dashed outline is 48. Note what is not 48: the pill's visible shape is 32, and the padding that brings it to the floor sits outside it — so the control stays the size it was drawn while the target clears the floor. Same for a breadcrumb step, which is text with 48 of height around it rather than a box drawn at 48.

The one deliberate exception

MxSearchField's clear button is 32. It sits inside a 48-high row, so the row is what the thumb aims at and this is the last few pixels of it — a 48-square button there would make the field 64 high. An exception that is written down and reasoned is a decision; an exception that is discovered later is a bug.
